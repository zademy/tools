# Codificación obligatoria ISO-8859-1

Este proyecto utiliza archivos heredados codificados estrictamente como
`ISO-8859-1` sin BOM.

## Regla crítica

Los archivos afectados nunca deben convertirse a UTF-8, UTF-8 con BOM,
Windows-1252 ni otra codificación.

Antes de crear, leer, modificar, reemplazar o guardar un archivo afectado,
debes preservar su codificación ISO-8859-1.

## Archivos afectados

Aplica estas reglas a:

- `src/main/java/**/*.java`
- `src/main/resources/**/*.properties`
- `src/main/resources/**/*.xml`
- `src/main/webapp/**/*.jsp`
- `src/main/webapp/**/*.js`
- `src/main/webapp/**/*.css`
- Cualquier archivo existente detectado como ISO-8859-1.

Ajusta esta lista según la estructura real del proyecto.

## Lectura de archivos

- No asumas que el contenido está en UTF-8.
- Para archivos ISO-8859-1, utiliza una herramienta especializada de lectura.
- Si no existe una herramienta especializada, utiliza Python indicando
  explícitamente `encoding="iso-8859-1"`.
- No interpretes caracteres dañados como contenido correcto.
- Si aparecen secuencias como `Ã¡`, `Ã©`, `Ã±` o caracteres de reemplazo,
  detén la modificación y verifica la codificación.

Ejemplo de lectura segura:

```bash
python3 -c "
from pathlib import Path
print(Path('ARCHIVO').read_text(encoding='iso-8859-1'))
"
```

## Escritura de archivos

- Utiliza una herramienta especializada para escribir ISO-8859-1.
- No utilices directamente herramientas que escriban siempre en UTF-8.
- Toda conversión debe ser estricta.
- Si un carácter no puede representarse en ISO-8859-1, informa el problema.
- Nunca elimines, reemplaces o transliteres silenciosamente caracteres.
- No uses opciones equivalentes a `IGNORE`, `TRANSLIT` o reemplazo automático.
- Conserva el tipo de salto de línea existente: `LF` o `CRLF`.
- Conserva la presencia o ausencia de una nueva línea final.
- No agregues BOM.

Ejemplo de escritura segura:

```python
from pathlib import Path

path = Path("ARCHIVO")
content = "contenido"

content.encode("iso-8859-1", errors="strict")
path.write_text(content, encoding="iso-8859-1", errors="strict")
```

## Caracteres permitidos

Antes de escribir, comprueba que todo el contenido pueda codificarse
estrictamente como ISO-8859-1.

Evita introducir caracteres que normalmente no son representables, como:

- Emojis.
- Comillas tipográficas.
- Guiones tipográficos.
- Símbolos Unicode especiales.
- Caracteres de otros alfabetos no incluidos en ISO-8859-1.

Usa equivalentes simples solo cuando no alteren el significado:

- Comillas rectas: `"` y `'`.
- Guion ASCII: `-`.
- Tres puntos ASCII: `...`.

No sustituyas caracteres automáticamente sin revisar el contexto.

## Verificación obligatoria

Después de modificar archivos afectados:

1. Verifica que no exista BOM.
2. Verifica que el contenido pueda codificarse como ISO-8859-1.
3. Revisa el diff para detectar texto corrupto o mojibake.
4. Comprueba que solo hayan cambiado las líneas necesarias.
5. Ejecuta las pruebas y la compilación del proyecto.
6. Ejecuta el validador de codificación del proyecto, si existe.

No declares una tarea terminada si alguna validación falla.

## Prohibiciones

- No conviertas todo el proyecto a UTF-8.
- No cambies la codificación como parte de una refactorización.
- No normalices archivos masivamente sin autorización explícita.
- No combines cambios funcionales con conversiones de codificación.
- No confíes únicamente en la extensión del archivo.
- No uses `file` como única garantía de codificación.
- No permitas que un formateador reescriba el archivo en UTF-8.
- No modifiques bytes ajenos a la sección solicitada.

## Archivos nuevos

Los archivos nuevos incluidos en las rutas afectadas también deben guardarse
como ISO-8859-1 sin BOM.

Antes de crear un archivo nuevo:

1. Genera el contenido como texto.
2. Verifica que sea representable en ISO-8859-1.
3. Escríbelo usando codificación explícita.
4. Verifica el archivo generado.
5. Ejecuta las pruebas correspondientes.

## Respuesta final del agente

Al finalizar una modificación, indica:

- Qué archivos ISO-8859-1 fueron modificados.
- Qué método se utilizó para preservar la codificación.
- Qué validación se ejecutó.
- Si se conservaron los saltos de línea originales.
