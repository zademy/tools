# Mandatory ISO-8859-1 Encoding

## Critical Rule

This project uses legacy files encoded strictly as `ISO-8859-1` without a BOM.
Never convert affected files to UTF-8, UTF-8 with a BOM, Windows-1252, or any
other encoding. Such conversion corrupts their bytes and content.

Preserve ISO-8859-1 whenever you create, detect, read, modify, replace, or save
an affected file.

## Affected Files

Apply this workflow to:

- `src/main/java/**/*.java`
- `src/main/resources/**/*.properties`
- `src/main/resources/**/*.xml`
- `src/main/webapp/**/*.jsp`
- `src/main/webapp/**/*.js`
- `src/main/webapp/**/*.css`
- Any existing file detected as ISO-8859-1.

Adjust this list to the project's actual structure. New files in affected paths
must also use ISO-8859-1 without a BOM.

## Detection

- Check the actual file encoding; the extension alone is insufficient.
- Do not use `file` as the sole encoding guarantee.
- Confirm that no BOM exists.

## Reading

- Do not assume UTF-8 content.
- Use a specialized reader for ISO-8859-1 files.
- If no specialized reader exists, use Python with
  `encoding="iso-8859-1"` explicitly.

Safe reading example:

```bash
python3 -c "
from pathlib import Path
print(Path('ARCHIVO').read_text(encoding='iso-8859-1'))
"
```

## Writing

- Use a specialized ISO-8859-1 writer. Do not directly use tools that always
  write UTF-8.
- Make every conversion strict.
- Report any character that ISO-8859-1 cannot represent. Never silently delete,
  replace, or transliterate characters.
- Do not use options equivalent to `IGNORE`, `TRANSLIT`, or automatic
  replacement.
- Preserve the existing line-ending type: `LF` or `CRLF`.
- Preserve the presence or absence of a final newline.
- Do not add a BOM.
- Prevent formatters from rewriting the file as UTF-8.
- Modify no bytes outside the requested section.

Safe writing example:

```python
from pathlib import Path

path = Path("ARCHIVO")
content = "contenido"

content.encode("iso-8859-1", errors="strict")
path.write_text(content, encoding="iso-8859-1", errors="strict")
```

For a new affected file:

1. Generate the content as text.
2. Confirm that ISO-8859-1 can represent it.
3. Write it with an explicit encoding.
4. Verify the generated file.
5. Run the relevant tests.

## Allowed Characters

Before writing, confirm that all content encodes strictly as ISO-8859-1.

Avoid introducing characters that are normally not representable, including:

- Emoji.
- Typographic quotation marks.
- Typographic dashes.
- Special Unicode symbols.
- Characters from alphabets not included in ISO-8859-1.

Use simple equivalents only when meaning remains unchanged:

- Straight quotation marks: `"` and `'`.
- ASCII hyphen: `-`.
- Three ASCII periods: `...`.

Review the context before substituting any character; never substitute
automatically.

## Mandatory Validation

After modifying affected files:

1. Confirm that no BOM exists.
2. Confirm that the content encodes as ISO-8859-1.
3. Inspect the diff for corrupt text or mojibake.
4. Confirm that only necessary lines changed.
5. Run the project's tests and build.
6. Run the project's encoding validator, if one exists.

For each completed modification, report:

- Which ISO-8859-1 files changed.
- Which method preserved the encoding.
- Which validation ran.
- Whether the original line endings were preserved.

## Failure Handling

- Stop and report any character that cannot be represented strictly in
  ISO-8859-1.
- Do not claim completion when any validation fails.
- Do not convert the entire project to UTF-8.
- Do not change encoding during a refactor.
- Do not normalize files in bulk without explicit authorization.
- Do not combine functional changes with encoding conversions.
